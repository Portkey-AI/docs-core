## Overview

Gateway Registration connects your self-hosted AI Gateway to the Portkey Control Plane. Once registered, the Data Plane can pull promt templates, routing configs,integrations, API keys etc.

The registration flow has three steps:

1. **Register Gateway** — provide a name, URL, and environment type
2. **Workspace Provisioning** — choose which workspaces can use this gateway
3. **Save the deployment configuration** — download and store the generated configuration for your deployment.

---

## Step 1: Register Gateway

Navigate to **Admin Settings → Gateway Registration** and click **Register New Gateway**.

Fill in the following fields:

| Field | Description |
|:------|:------------|
| **Gateway Name** | A human-readable label for this gateway (e.g., `dev-ateway`, `prod-gateway`). |
| **Gateway Type** | Select if it is **Production** or **Non Production** gateway deployment. |

---

## Step 2: Workspace Provisioning

<Note>
  Workspace Provisioning is available on the **Hybrid Enterprise plan** only.
</Note>

Choose which workspaces in your organisation will have access to this gateway.


### Workspace Access Options

<Tabs>
  <Tab title="Allow All Workspaces">
    All current and future workspaces in your organisation can route traffic through this gateway. No further configuration is needed.
  </Tab>
  <Tab title="Allow Specific Workspaces">
    Only the workspaces you explicitly enable will have access to this gateway.
    This is useful when you need separate gateways for different teams, business units, or compliance boundaries.
  </Tab>
</Tabs>

Click **Next** to continue.

---

## Step 3: Save the deployment configuration

Download the `values.yaml` configuration file generated for your deployment.

<Warning>
  **Save this configuration before leaving.** It will not be accessible again after you navigate away from this screen. Use the **Download values.yaml** button to save a local copy.
</Warning>

## Gateway Overview

After registration, you can manage your gateway from **Admin Settings → Gateway Registration → [Gateway Name]**.

The overview page shows:

- **Status badge** (`active` / `inactive`) — updated when you run Verify Connection.
- **Workspace Control tab** — edit workspace access permissions after registration.
- **Last Sync** — elapsed time since the most recent sync between the data plane and control plane.

## Rotate the Gateway Authentication Key

Each registered gateway authenticates to Portkey with an auth key. Set it as the `PORTKEY_CLIENT_AUTH` value in your deployment. Rotate it from the gateway's overview page, for example after a suspected exposure or on a regular schedule.

<Steps>
<Step title="Open the deployment">
Go to **Admin Settings → Gateway Registration** and open the deployment. In the **Gateway Authentication** card, click **Rotate Key**.

<Frame>
  <img src="/images/self-hosting/gateway-auth-rotate-key.png" alt="Gateway Authentication card with a Rotate Key button" />
</Frame>
</Step>
<Step title="Set a grace period">
Enter a **Grace period (hours)**, from 0 to 24, for how long the previous key keeps working. Leave it empty to use the default. Click **Confirm Rotation**.

<Frame>
  <img src="/images/self-hosting/gateway-auth-grace-period.png" alt="Rotate key dialog with an optional Grace period in hours and a Confirm Rotation button" />
</Frame>
</Step>
<Step title="Copy the new key">
Copy the new key and store it in your secret store. It is shown only once.

<Frame>
  <img src="/images/self-hosting/gateway-auth-new-key.png" alt="New gateway authentication key shown once, with copy and Done controls" />
</Frame>
</Step>
<Step title="Update every deployed gateway">
Set `PORTKEY_CLIENT_AUTH` to the new key in each gateway deployment that uses this registration, then restart the gateways.
</Step>
<Step title="Verify the connection">
Open the deployment and click **Verify Connection**. Confirm the status is **Active** and **Last Sync** updates.
</Step>
</Steps>

<Warning>
  Gateways still using the old key stop working once the grace period ends. With a grace period of `0`, the old key stops working immediately and gateways lose sync until you deploy the new key. Pick a grace period long enough to update and restart every gateway.
</Warning>

## Disable the SaaS Gateway

The **SaaS Gateway** toggle at the top of the Gateway Registration page controls whether your organisation can send traffic to the Portkey SaaS gateway. Turn it off to route all traffic through your own registered gateways.

<Frame>
  <img src="/images/self-hosting/saas-gateway-toggle.png" alt="SaaS Gateway toggle on the Gateway Registration page, shown as Disabled" />
</Frame>

When the toggle is **Disabled**, the SaaS AI gateway and the SaaS MCP gateway do not accept traffic for your account. Requests only work through gateways you have registered.

<Note>
  The toggle is available on all accounts. Only organisation admins can change it.
</Note>

<Warning>
  Point your applications and MCP clients at your registered gateways **before** disabling the SaaS Gateway. Requests that still use the SaaS gateway are not allowed once it is disabled.
</Warning>

### Disable or re-enable

<Steps>
<Step title="Open Gateway Registration">
Go to **Settings > Organisation > Gateway Registration**.
</Step>
<Step title="Confirm a registered gateway is active">
Check that at least one registration shows an **Active** status.
</Step>
<Step title="Switch the SaaS Gateway toggle">
Turn the **SaaS Gateway** toggle off to disable the SaaS gateway, or on to re-enable it.
</Step>
</Steps>

## Connect to the Gateway

Once your gateway is running and registered, verify it is reachable and routing requests correctly.

```bash
curl '<GATEWAY_BASE_URL>/v1/chat/completions' \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <OPENAI_API_KEY>" \
  -H "x-portkey-provider: openai" \
  -H "x-portkey-api-key: <PORTKEY_API_KEY>" \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [{"role": "user", "content": "What is a fractal?"}]
  }'
```

Replace the following before running:

| Placeholder | Value |
|:------------|:------|
| `GATEWAY_BASE_URL` | The DNS record pointing to your deployed gateway |
| `OPENAI_API_KEY` | Your OpenAI API key |
| `PORTKEY_API_KEY` | Your Portkey API key |
