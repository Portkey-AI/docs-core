The Admin API configures the gateway. The [Gateway API](/aigw/api-reference/inference-api/introduction) runs inference through it.

Two planes, two credentials. Connecting a model provider, capping a team's spend, registering an MCP server, issuing an API key, pulling last month's cost — all of it happens here, and none of it travels on the inference request path.

<Warning>
Admin API requests are authorised with a **Strata Cloud Manager access token**, not a gateway API key. A key that works on `/chat/completions` returns `401` here. See [Authentication](/aigw/api-reference/admin-api/authentication).
</Warning>

## Your first request

<Steps>
  <Step title="Get a token">
    Exchange a service account's credentials for an access token scoped to your tenant.

    ```sh
    curl -d "grant_type=client_credentials&scope=tsg_id:<tsg_id>" \
      -u <client_id>:<client_secret> \
      -H "Content-Type: application/x-www-form-urlencoded" \
      -X POST https://auth.apps.paloaltonetworks.com/oauth2/access_token
    ```

    [Create a service account](/aigw/api-reference/admin-api/authentication#create-a-service-account) if you do not have one yet.
  </Step>
  <Step title="Call an endpoint">
    Send the token as a bearer token. Every endpoint in this tab takes the same header.

    ```sh
    curl "$ADMIN_API_BASE_URL/configs" \
      -H "Authorization: Bearer $ACCESS_TOKEN"
    ```

    The response lists the configs belonging to the organisation the token is scoped to. No tenant identifier is sent on the request — the token carries it.
  </Step>
  <Step title="Keep going">
    Tokens expire after **15 minutes**. Refresh before each batch of calls rather than caching one for the life of a job.
  </Step>
</Steps>

<Info>
`$ADMIN_API_BASE_URL` stands in for the server shown on each endpoint's reference page.
</Info>

## How resources are scoped

Every resource in the Admin API sits at one of two levels. Knowing which one you are addressing explains most 403s.

| Level | Addressed by | Holds |
|:--|:--|:--|
| **Organisation** | The TSG ID inside your token. One TSG is one organisation. | Org guardrails, usage and rate limit policies, API keys, deployments |
| **Workspace** | A `workspace_id`, passed explicitly | Configs, integrations, providers, workspace guardrails |

To reach a workspace-level resource, pass `workspace_id` as a **query parameter** on `GET` and list requests, and in the **request body** on `POST` and `PUT`. A workspace UUID or a slug both work.

```sh
curl "$ADMIN_API_BASE_URL/configs?workspace_id=WORKSPACE_SLUG" \
  -H "Authorization: Bearer $ACCESS_TOKEN"
```

Omit it and the call resolves against the organisation default.

### Slugs and IDs

Which identifier a path takes is not arbitrary, and mixing them up is the second most common cause of a `404`:

- **Slugs** — the resources you name yourself: `/configs/{slug}`, `/integrations/{slug}`, `/providers/{slug}`
- **IDs** — the resources the gateway names for you: `/guardrails/{guardrailId}`, `/mcp-servers/{mcpServerId}`, `/policies/usage-limits/{policyUsageLimitsId}`, `/api-keys/{id}`

## The map

Six groups, mirroring the sidebar.

| Group | Manages | Principal paths |
|:--|:--|:--|
| **Gateway Configuration** | Routing configs and the guardrails attached to a workspace | `/configs` · `/guardrails` |
| **Providers and Credentials** | Model providers, the credentials behind them, which workspaces and models are provisioned, and references to external vaults | `/integrations` · `/providers` · `/secret-references` |
| **MCP** | MCP integrations and servers, their capabilities, connections and per-user access | `/mcp-integrations` · `/mcp-servers` |
| **Administration** | API keys, registered gateway deployments, organisation-wide guardrails, usage and rate limit policies | `/api-keys` · `/deployments` · `/admin/v2/guardrails` · `/policies/*` |
| **Observability** | Cost, latency, token, error and cache analytics; log retrieval; feedback | `/analytics/*` · `/logs` · `/feedback` |
| **API Reference** | This page, [Authentication](/aigw/api-reference/admin-api/authentication) and [Errors](/aigw/api-reference/admin-api/error) | — |

<Note>
**Guardrails exist at both levels, on two different paths.** `/guardrails` manages the guardrails of a single workspace. `/admin/v2/guardrails` manages the organisation-wide ones that apply to every workspace unless a workspace is explicitly excluded. See [Enforcing Org Level Guardrails](/aigw/product/administration/enforce-organisation-level-guardrails).
</Note>

## Common tasks

Each of these is a sequence of calls, not a single endpoint.

<AccordionGroup>
  <Accordion title="Connect a model provider and provision it to a team" icon="plug">
    1. `POST /integrations` — create the integration and attach the provider credential
    2. `PUT /integrations/{slug}/models` — choose which models the integration exposes
    3. `PUT /integrations/{slug}/workspaces` — grant the workspaces that may use it

    Steps 2 and 3 are [model provisioning](/aigw/product/model-catalog/model-provisioning) and [workspace provisioning](/aigw/product/model-catalog/workspace-provisioning). Skip them and the integration exists but nobody can reach it.
  </Accordion>
  <Accordion title="Put an MCP server behind the gateway" icon="server">
    1. `POST /mcp-servers` — register the server
    2. `GET /mcp-servers/{mcpServerId}/capabilities` — read the tools it advertises
    3. `PUT /mcp-servers/{mcpServerId}/capabilities` — enable only the tools you intend to expose
    4. `PUT /mcp-servers/{mcpServerId}/user-access` — decide who may call it
    5. `POST /mcp-servers/{mcpServerId}/test` — confirm the connection before anyone depends on it

    See the [MCP Gateway](/aigw/product/mcp-gateway) documentation for what each capability means.
  </Accordion>
  <Accordion title="Cap what a team can spend" icon="gauge">
    1. `POST /policies/usage-limits` — define the budget
    2. `GET /policies/usage-limits/{policyUsageLimitsId}/entities` — see what the policy currently binds to
    3. `PUT /policies/usage-limits/{policyUsageLimitsId}/entities/{entityId}/reset` — clear consumption for one entity

    Rate limits work the same way under `/policies/rate-limits`. Background in [Budget Limits](/aigw/product/policies/budget-limits) and [Rate Limits](/aigw/product/policies/rate-limits).
  </Accordion>
  <Accordion title="Issue and rotate a gateway API key" icon="key">
    1. `POST /api-keys/{type}/{sub-type}` — create the key with the scopes it needs
    2. `POST /api-keys/{id}/rotate` — rotate on a schedule or on suspicion

    These are the keys your applications send on **inference** requests. Creating one is an administrative act, so the call itself is authorised with an access token. Scopes are listed in [API Keys (AuthN and AuthZ)](/aigw/product/enterprise-offering/org-management/api-keys-authn-and-authz).
  </Accordion>
  <Accordion title="Report on last month" icon="chart-line">
    - `GET /analytics/graphs/cost` — spend over time
    - `GET /analytics/groups/ai-models` — spend broken down by model
    - `GET /analytics/groups/metadata/{metadataKey}` — spend broken down by whatever your requests tag themselves with

    Tagging requests with [metadata](/aigw/product/observability/metadata) is what makes the last one useful.
  </Accordion>
</AccordionGroup>

## When a call fails

| Status | Read it as |
|:--|:--|
| `401` | The token is expired, malformed, or is actually a gateway API key |
| `403` | The token is valid but scoped to a different tenant, or the service account's role does not cover this operation |
| `404` | A slug was passed where an ID was expected — or the resource belongs to a workspace you did not name |
| `409` | The resource already exists. Most creates are not idempotent |

Every code the Admin API returns is listed on the [Errors](/aigw/api-reference/admin-api/error) page.

## Audit

Every administrative call is recorded with the principal that made it, the action, the target resource, a timestamp, an IP address and the request details. Automation is attributable to the service account that ran it, which is a good reason to give each one a name that says what it is for.
