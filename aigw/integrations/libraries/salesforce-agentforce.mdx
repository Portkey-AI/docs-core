Salesforce lets you bring your own model (BYOLLM) to Agentforce through the [LLM Open Connector](https://opensource.salesforce.com/einstein-platform/docs/apis/llm-open-connector). The connector speaks a subset of the OpenAI Chat Completions API, so the AI Gateway's `/v1/chat/completions` endpoint works with it directly. You don't need middleware.

With the AI Gateway in between, Salesforce can use any model in your Model Catalog, and every request shows up in the AI Gateway logs with cost, latency and token counts.

## Prerequisites

- [AI Gateway API key](https://stratacloudmanager.paloaltonetworks.com/)
- Provider configured in [Model Catalog](https://stratacloudmanager.paloaltonetworks.com/)
- Salesforce org with Data Cloud and Einstein generative AI enabled, and permission to use Model Builder

## Setup

<Steps>
<Step title="Configure the AI Gateway">
1. Go to [Model Catalog](https://stratacloudmanager.paloaltonetworks.com/) → **Add Provider**.
2. Select your provider (OpenAI, Anthropic, Bedrock, etc.), enter its credentials, and set a slug like `openai-prod`.
3. Go to [API Keys](https://stratacloudmanager.paloaltonetworks.com/) → **Create new key** → Save.

The model ID you give Salesforce is `@<provider-slug>/<model>`, for example `@openai-prod/gpt-5`.
</Step>

<Step title="Test the endpoint">
Salesforce sends a request like this one. Run it first to confirm the key and model work:

```sh
curl https://aigw.portkey.ai/v1/chat/completions \
    -H "Content-Type: application/json" \
    -H "x-portkey-api-key: $AI_GATEWAY_API_KEY" \
    -d '{
        "model": "@openai-prod/gpt-5",
        "messages": [
            {"role": "system", "content": "You are a helpful assistant."},
            {"role": "user", "content": "What is the capital of Canada?"}
        ],
        "max_tokens": 200,
        "temperature": 0.7,
        "n": 1
    }'
```

On a hybrid deployment, replace `https://aigw.portkey.ai` with your gateway's URL.
</Step>

<Step title="Add the AI Gateway as a foundation model">
1. In Salesforce, open **Einstein Studio** (in the Data Cloud app) and go to **Model Builder**.
2. Click **Add Foundation Model**, then choose to connect your own LLM with the **LLM Open Connector**.
3. Fill in the connection:

| Field | Value |
|-------|-------|
| **URL** | `https://aigw.portkey.ai/v1/chat/completions` |
| **Auth Header** | `x-portkey-api-key` |
| **Auth Key** | Your AI Gateway API key |
| **Model Name** | A Model Catalog ID, e.g. `@openai-prod/gpt-5` |

4. Save the connection.

<Note>
Salesforce sends one auth header and nothing else, so you can't add other `x-portkey-*` headers here. To route or add fallbacks, attach a default config to the API key ([see below](#add-fallbacks-and-routing)).
</Note>
</Step>

<Step title="Create a configured model">
1. Select the new model in the **Model Library** and click **New Configuration**.
2. Send a prompt in the **Model Playground**.
3. Check that the request appears in the AI Gateway [logs](/aigw/product/observability/logs) in [Strata Cloud Manager](https://stratacloudmanager.paloaltonetworks.com/).
4. Save the configuration.
</Step>
</Steps>

## Use the model in Salesforce

Once saved, the configured model is available wherever Salesforce lets you pick a generative model:

- **Prompt Builder**: select it as the model for a prompt template.
- **Agentforce**: add a prompt template that uses the model to an agent as an action.
- **Models API**: call it by its API name from Apex or REST. Find the API name on the configured model's detail page.

<Note>
The LLM Open Connector supports text chat only. It doesn't send tool definitions, images or streaming requests. Use the AI Gateway model for prompt templates and Models API calls, not for features that need tool calling.
</Note>

## Add fallbacks and routing

Salesforce can't send `x-portkey-config`, so attach a [default config](/aigw/product/administration/enforce-default-config) to the API key you entered in Model Builder. Every request from Salesforce then uses that config.

Example: try OpenAI first, fall back to Anthropic on errors:

```json
{
    "strategy": { "mode": "fallback" },
    "targets": [
        {
            "provider": "@openai-prod",
            "override_params": { "model": "gpt-5" }
        },
        {
            "provider": "@anthropic-prod",
            "override_params": { "model": "claude-opus-4-7" }
        }
    ]
}
```

1. Create the config in **Configs** in [Strata Cloud Manager](https://stratacloudmanager.paloaltonetworks.com/) and copy its ID.
2. Go to **API Keys**, edit the key Salesforce uses, and select the config.

`override_params` rewrites the model in each request, so the **Model Name** in Salesforce becomes a label. Keep it in `@slug/model` form anyway so the connection still works if the config is removed.

To cap spend for Salesforce traffic, set [budget limits](/aigw/product/policies/budget-limits) on the integration for the workspace the API key belongs to, or give Salesforce its own workspace.

## Troubleshooting

| Problem | Fix |
|---------|-----|
| `401` when saving or testing | Set **Auth Header** to `x-portkey-api-key` and **Auth Key** to the raw key, with no `Bearer` prefix. |
| Model not found | The **Model Name** must use a provider slug that exists in the API key's workspace, e.g. `@openai-prod/gpt-5`. |
| Connection fails on save | The URL must end in `/chat/completions` and be reachable on HTTPS port 443. |
| Hybrid gateway unreachable | Expose the gateway over public HTTPS and allow Salesforce's BYO model IP ranges, listed in Salesforce's *IP Addresses and Domains to Allow* article. |
| Provider rejects the `parameters` field | Salesforce can nest extra settings in a `parameters` object. Add `"drop_params": ["parameters"]` to the target in the key's default config. |
