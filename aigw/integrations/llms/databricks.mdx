The AI Gateway provides a robust and secure gateway to integrate various Large Language Models (LLMs) into applications, including [Databricks Model Serving](https://docs.databricks.com/en/machine-learning/model-serving/index.html) endpoints.

With the AI Gateway, take advantage of features like fast AI gateway access, observability, prompt management, and more, while securely managing API keys through [Model Catalog](/aigw/product/model-catalog).

<Note>
Provider Slug: `databricks`
</Note>

## How It Works

By default, AI Gateway routes requests to Databricks' [AI Gateway](https://docs.databricks.com/aws/en/machine-learning/foundation-model-apis/api-reference) endpoint (`/ai-gateway/...`) when no serving endpoint name is specified. This uses Databricks' pay-per-token Foundation Model APIs.

If you specify a `databricksServingEndpointName` (or `databricks_serving_endpoint_name`) in your provider configuration, the AI Gateway will route to `/serving-endpoints/<name>/invocations` instead, which is useful for provisioned throughput endpoints or custom model deployments.

<Info>
**Pricing in Logs:** Databricks currently only supports [custom pricing](/aigw/product/model-catalog/custom-models). Cost data will only appear in your AI Gateway logs if you configure custom pricing for your Databricks models in the Model Catalog.
</Info>

## Quick Start

Get Databricks working in 3 steps:

<CodeGroup>


```python OpenAI Py icon="python"
from openai import OpenAI

# 1. Install: pip install openai portkey-ai
# 2. Add @databricks provider in model catalog
# 3. Use it:

client = OpenAI(
    api_key="PORTKEY_API_KEY",  # Portkey API key
    base_url="https://aigw.portkey.ai/v1"
)

response = client.chat.completions.create(
    model="@databricks/databricks-meta-llama-3-1-70b-instruct",
    messages=[{"role": "user", "content": "Say this is a test"}]
)

print(response.choices[0].message.content)
```

```js OpenAI JS icon="square-js"
import OpenAI from "openai"

// 1. Install: npm install openai portkey-ai
// 2. Add @databricks provider in model catalog
// 3. Use it:

const client = new OpenAI({
    apiKey: "PORTKEY_API_KEY",  // Portkey API key
    baseURL: "https://aigw.portkey.ai/v1"
})

const response = await client.chat.completions.create({
    model: "@databricks/databricks-meta-llama-3-1-70b-instruct",
    messages: [{ role: "user", content: "Say this is a test" }]
})

console.log(response.choices[0].message.content)
```

```sh cURL icon="square-terminal"
# 1. Add @databricks provider in model catalog
# 2. Use it:

curl https://aigw.portkey.ai/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PORTKEY_API_KEY" \
  -d '{
    "model": "@databricks/databricks-meta-llama-3-1-70b-instruct",
    "messages": [
      { "role": "user", "content": "Say this is a test" }
    ]
  }'
```
</CodeGroup>

<Note>
**Tip:** You can also set `provider="@databricks"` in `Portkey()` and use just `model="databricks-meta-llama-3-1-70b-instruct"` in the request.
</Note>

## Add Provider in Model Catalog

1. Go to [**Model Catalog → Add Provider**](https://stratacloudmanager.paloaltonetworks.com/)
2. Select **Databricks**
3. Choose existing credentials or create new by entering your [Databricks personal access token](https://docs.databricks.com/en/dev-tools/auth/pat.html) and workspace name
4. Name your provider (e.g., `databricks-prod`)

### Configuration Parameters

| Parameter | Description | Required |
|-----------|-------------|----------|
| `apiKey` | Databricks personal access token | Yes |
| `databricksWorkspace` | Databricks workspace name (used to construct the URL: `https://<workspace>.cloud.databricks.com`) | Yes |
| `databricksServingEndpointName` | Name of a specific serving endpoint. When set, requests route to `/serving-endpoints/<name>/invocations` instead of the default AI Gateway endpoint. | No |

When using headers directly, pass the workspace name via the `x-portkey-databricks-workspace` header and the serving endpoint name via the `x-portkey-databricks-serving-endpoint-name` header.

## Embeddings

Generate embeddings using Databricks-hosted embedding models:

<CodeGroup>


```sh cURL
curl https://aigw.portkey.ai/v1/embeddings \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PORTKEY_API_KEY" \
  -d '{
    "model": "@databricks/databricks-bge-large-en",
    "input": "The quick brown fox jumps over the lazy dog"
  }'
```
</CodeGroup>

## Responses API

Use the OpenAI Responses API format with Databricks models:

<CodeGroup>


```sh cURL
curl https://aigw.portkey.ai/v1/responses \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PORTKEY_API_KEY" \
  -d '{
    "model": "@databricks/databricks-meta-llama-3-1-70b-instruct",
    "input": "Tell me a three sentence bedtime story about a unicorn."
  }'
```
</CodeGroup>

## Messages API

Use the Anthropic Messages API format with Databricks-hosted Anthropic models (e.g., Claude):

<Note>
The `/messages` endpoint is only supported for Anthropic models deployed on Databricks. It routes to Databricks' `/ai-gateway/anthropic/v1/messages` endpoint.
</Note>

<CodeGroup>


```sh cURL
curl https://aigw.portkey.ai/v1/messages \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PORTKEY_API_KEY" \
  -d '{
    "model": "@databricks/claude-sonnet-4-20250514",
    "max_tokens": 250,
    "messages": [
      { "role": "user", "content": "Say this is a test" }
    ]
  }'
```
</CodeGroup>

## Supported Models

Databricks Model Serving supports a variety of foundation models and custom endpoints:

- **Meta Llama Models**: `databricks-meta-llama-3-1-70b-instruct`, `databricks-meta-llama-3-1-405b-instruct`
- **DBRX**: `databricks-dbrx-instruct`
- **Embedding Models**: `databricks-bge-large-en`, `databricks-gte-large-en`
- **Custom Endpoints**: Any model deployed as a Databricks serving endpoint

For the complete list of available models, refer to the [Databricks Foundation Model APIs documentation](https://docs.databricks.com/en/machine-learning/foundation-model-apis/index.html).
