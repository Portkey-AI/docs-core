[Cato Networks](https://www.catonetworks.com/) provides AI security inspection for LLM traffic via the analyze API.

<Note>
Requires Backend `v1.17.0+`.
</Note>

## Using Cato with Prisma AIRS AI Gateway

### 1. Add Cato Credentials to the AI Gateway

* Navigate to `Admin Settings` → `Plugins`
* Edit the **Cato Networks** integration
* Add your **API Key** (`apiKey`, required)
* Add the **API Base URL** (`apiBase`, optional). Default: `https://api.aisec.catonetworks.com`

### 2. Add Cato Guardrail Check

* Navigate to `Guardrails` → `Create`
* Search for **"Cato Networks Guardrail"** and click `Add`
* Configure:
  * **Application Name** (`appName`, optional) — sent to Cato as `x-cato-gateway-key-alias`, for tracking
  * **Timeout** (`timeout`, default `5000` ms)
* Set guardrail actions and create the guardrail

| Check Name | Description | Parameters | Supported Hooks |
|------------|-------------|------------|-----------------|
| Cato Networks Guardrail | Inspects content via Cato analyze API; can monitor, anonymize, or block | `appName`, `timeout` | `beforeRequestHook`, `afterRequestHook` |

To pass a user email or session ID to Cato, send the `x-cato-user-email` or `x-cato-session-id` header on your request. The AI Gateway forwards them to Cato. The `userEmail` and `keyAlias` parameters from earlier versions are no longer read.

### 3. Attach to a Config

```json
{
  "input_guardrails": ["guardrails-id-xxx"],
  "output_guardrails": ["guardrails-id-yyy"]
}
```

See [Configs](/aigw/product/ai-gateway/configs) for usage with SDKs and the gateway.

## When Cato Blocks a Request

If Cato returns a block action, the check fails. With synchronous guardrails (`async=false`), the reason is in the `data` field of the check. Input checks are in `hook_results.before_request_hooks[].checks[].data`. Output checks are in `hook_results.after_request_hooks[].checks[].data`.

```json
{
  "action": "block",
  "detection_message": "Sensitive content detected"
}
```

* `action` is always `block`.
* `detection_message` is the message from Cato. It is `null` if Cato sends no message.
* For monitor and anonymize actions, `data` is `null`.

With `async=false` and `deny=true`, a failed check returns `446`. Async guardrails (the default) only log the result. Output guardrails on a streaming request run after the stream ends, so they cannot block it. To see `hook_results` in a stream, set `x-portkey-strict-open-ai-compliance: false`. See [Streaming](/aigw/product/guardrails/capabilities#streaming). See [Guardrails](/aigw/product/guardrails) and [Sync vs. Async](/aigw/product/guardrails/capabilities#sync-vs-async).
