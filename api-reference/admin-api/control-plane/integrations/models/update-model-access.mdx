Bulk-update which models an integration can use, plus optional per-model routing and pricing.

## Understanding `override_existing_model_access`

| Value | Behavior |
| :--- | :--- |
| `true` | All existing models are archived (disabled) first, then only the models you pass are set to active. Use this when you want to **restrict** access to an explicit subset. |
| `false` (default) | The models you pass are upserted into the existing list. Models not included in your request are left unchanged. This is an **additive** operation. |

<Warning>
Since integrations now have a pre-populated model list at creation time, using `override_existing_model_access: false` (the default) with a subset of models will **not** restrict access — the other pre-populated models remain in their current state. To restrict access to specific models, always set `override_existing_model_access: true`.
</Warning>

## Per-model configurations

Each item in `models` accepts an optional `configurations` object:

| Field | Type | Description |
| :---- | :--- | :---------- |
| `custom_host` | string | Upstream base URL for this model. Must be a valid URL when set. |
| `custom_headers` | object | String-to-string map of headers sent with requests for this model. |

### Precedence

- **Model-level** `custom_headers` override **integration-level** `custom_headers` for that model.
- A request-time / header-level `custom_host` still takes priority over a model-level `custom_host`.

See [Custom hosts](/product/ai-gateway/custom-hosts) and [Custom models](/product/model-catalog/custom-models#per-model-custom-host-and-headers).

### Example

```bash
curl -X PUT "https://api.portkey.ai/v1/integrations/openai-prod/models" \
  -H "Content-Type: application/json" \
  -H "x-portkey-api-key: $PORTKEY_API_KEY" \
  -d '{
    "models": [
      {
        "slug": "my-custom-model-v1",
        "enabled": true,
        "is_custom": true,
        "base_model_slug": "gpt-4o",
        "configurations": {
          "custom_host": "https://llm.internal.example.com/v1",
          "custom_headers": {
            "x-tenant-id": "acme-prod",
            "x-region": "us-east-1"
          }
        }
      }
    ]
  }'
```

`custom_headers` values must be strings. Nested objects or non-string values are rejected.
