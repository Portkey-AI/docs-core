[HoneyHive](https://www.honeyhive.ai) is an AI observability and evaluation platform for agents and LLM applications. Portkey exposes an OpenAI-compatible API, so HoneyHive traces every request routed through the gateway with the OpenInference OpenAI instrumentor. No Portkey-specific instrumentor is required.

This integration allows you to:
- Trace requests routed through Portkey, whichever provider handles them
- Keep Portkey's routing, fallbacks, load balancing, and caching, and view each request as a HoneyHive trace
- Group gateway calls into named spans alongside your own application logic
- Run HoneyHive evaluators and experiments on the same traces

## Quick Start

### Prerequisites

- Python 3.11 or later
- Portkey account with an API key
- A provider added in Portkey's [Model Catalog](/product/model-catalog) (for example, `openai-prod`)
- HoneyHive account with an [ingestion API key](https://docs.honeyhive.ai/v2/workspace/api-keys#ingestion-keys)

### Installation

```bash
pip install honeyhive openinference-instrumentation-openai openai portkey-ai
```

### Basic Setup

```python
import os

from openai import OpenAI
from portkey_ai import PORTKEY_GATEWAY_URL
from honeyhive import HoneyHiveTracer
from openinference.instrumentation.openai import OpenAIInstrumentor

# Reads HH_INGESTION_API_KEY from your environment
tracer = HoneyHiveTracer.init()
OpenAIInstrumentor().instrument(tracer_provider=tracer.provider)

# Point the OpenAI client at Portkey's gateway
client = OpenAI(
    api_key=os.getenv("PORTKEY_API_KEY"),
    base_url=PORTKEY_GATEWAY_URL,
)

# Use the @provider-slug/model format from Model Catalog
response = client.chat.completions.create(
    model="@openai-prod/gpt-4o-mini",
    messages=[{"role": "user", "content": "Hello, world!"}],
)

print(response.choices[0].message.content)
```

Set the HoneyHive key before you run the script:

```bash
export HH_INGESTION_API_KEY="your-honeyhive-ingestion-key"
export PORTKEY_API_KEY="your-portkey-api-key"
```

Set `HH_API_URL` if your HoneyHive data plane URL differs from the default.

<Note>
Call `instrument()` before you make any requests. Pass `tracer_provider=tracer.provider` so spans go to HoneyHive even when another OpenTelemetry provider is already set.
</Note>

## What Gets Traced

The OpenAI instrumentor captures every call that goes through the gateway:

- **Chat completions**: inputs, outputs, and token usage across providers
- **Tool and function calls**: arguments and results
- **Streaming responses**: streamed completions with aggregated tokens

## Using Portkey Features with HoneyHive

### 1. Multiple Providers

Change the model slug to switch providers. Each `@provider-slug` maps to credentials in Model Catalog:

```python
# Uses the tracer and client from Basic Setup
from honeyhive import trace

@trace
def query_multiple_providers():
    openai_response = client.chat.completions.create(
        model="@openai-prod/gpt-4o-mini",
        messages=[{"role": "user", "content": "Explain quantum computing briefly."}],
    )

    anthropic_response = client.chat.completions.create(
        model="@anthropic-prod/claude-sonnet-4-5-20250929",
        messages=[{"role": "user", "content": "Explain quantum computing briefly."}],
        max_tokens=250,
    )

    return openai_response, anthropic_response

query_multiple_providers()
```

The `@trace` decorator groups both calls under one span in HoneyHive.

### 2. Fallbacks and Load Balancing

Create a [config](/product/ai-gateway/configs) in the Portkey dashboard and pass its ID in the default headers. HoneyHive traces whichever provider handles the request:

```python
import os

from openai import OpenAI
from portkey_ai import PORTKEY_GATEWAY_URL, createHeaders
from honeyhive import trace

# Run after the tracer and instrumentor from Basic Setup
client = OpenAI(
    api_key=os.getenv("PORTKEY_API_KEY"),
    base_url=PORTKEY_GATEWAY_URL,
    default_headers=createHeaders(
        api_key=os.getenv("PORTKEY_API_KEY"),
        config=os.getenv("PORTKEY_CONFIG_ID"),
    ),
)

@trace
def resilient_completion(prompt: str):
    return client.chat.completions.create(
        model="@openai-prod/gpt-4o",
        messages=[{"role": "user", "content": prompt}],
    )

resilient_completion("What are the benefits of AI observability?")
```

Example config for fallback between providers:

```json
{
  "strategy": { "mode": "fallback" },
  "targets": [
    { "override_params": { "model": "@openai-prod/gpt-4o" } },
    { "override_params": { "model": "@anthropic-prod/claude-sonnet-4-5-20250929" } }
  ]
}
```

## Observability Features

### In HoneyHive:
- Trace tree for each request, with inputs, outputs, and token usage
- Session grouping and custom spans around gateway calls
- Evaluators and experiments on production traces
- Filtering by user, session, and custom metadata

### In Portkey:
- Request logs with provider details
- Analytics across providers
- Cost tracking and budgets
- Performance metrics

## Troubleshooting

### Traces not appearing

- Confirm `HH_INGESTION_API_KEY` is set.
- Initialize `OpenAIInstrumentor` with `tracer_provider=tracer.provider` before the first request.
- Point the OpenAI client at `PORTKEY_GATEWAY_URL` (`https://api.portkey.ai/v1`).

### Requests failing with provider errors

- Use the `@provider-slug/model-name` format, for example `@openai-prod/gpt-4o-mini`.
- Match the provider slug to a provider in [Model Catalog](/product/model-catalog).

### Gateway and direct calls look the same

The OpenAI instrumentor traces a Portkey client and a direct OpenAI client in the same app in the same way. Wrap related calls in `@trace` to group them under a named span.
