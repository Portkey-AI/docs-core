[FlashData](https://flashdata.dev/?utm_source=portkey&utm_medium=integration&utm_campaign=intent_gtm_2026q4&utm_content=mcp-overview) provides structured Google and YouTube data through a hosted MCP server. Use it to build source lists, news briefings, local business shortlists, and summaries of existing YouTube captions.

## Connect through Portkey

Create a [FlashData API key](https://flashdata.dev/app/api-keys) with the required source permissions. Data queries consume the key owner's [FlashData Credits](https://flashdata.dev/pricing). Account and pricing reads are free. Portkey and model usage have separate billing.

In **MCP Registry → Add MCP Integration**, configure:

| Field | Value |
| --- | --- |
| Name | `FlashData` |
| Slug | A unique slug, such as `flashdata-personal` |
| Server URL | `https://data.flashdata.dev/mcp` |
| Transport | HTTP (Streamable HTTP) |
| Authentication | Custom headers |
| Header | `X-API-Key: <YOUR_FLASHDATA_API_KEY>` |

The corresponding authentication configuration is:

```json
{
    "mcp_integration_details": {
        "transport": "http",
        "auth_type": "custom",
        "configurations": {
            "headers": {
                "X-API-Key": "<YOUR_FLASHDATA_API_KEY>"
            }
        }
    }
}
```

Restrict access to the intended workspace in **Access Control & Limits**. Connect an MCP client using a Portkey API key with **MCP Invoke** permission:

```json
{
    "mcpServers": {
        "flashdata": {
            "url": "https://mcp.portkey.ai/flashdata-personal/mcp",
            "headers": {
                "x-portkey-api-key": "<YOUR_PORTKEY_API_KEY>"
            }
        }
    }
}
```

Replace the slug with the one configured in the registry. Store actual keys in the relevant secret settings, outside source control and chat messages.

<Warning>
Portkey [custom authentication](/product/mcp-gateway/authentication/custom-auth) shares the configured upstream key across everyone granted access to that integration. For users paying from their own FlashData accounts, create separate integrations with each user's own key and isolate workspace access. A shared integration charges its configured key owner's Credits. FlashData uses API key authentication, without per-user OAuth. Portkey blocks forwarding or renaming headers to `X-API-Key`; client-side header forwarding cannot provide per-user keys here.
</Warning>

## Verify the connection

Discover the available tools, then ask the client:

```text
Use FlashData get_pricing with source "google_search" and request_count 1.
Do not run a search or any other paid data query.
```

This reads the current rate without spending FlashData Credits. It verifies authenticated connectivity, not paid retrieval. Tool discovery depends on the key's source permissions and Portkey's tool provisioning.

## Run a web search

After approving the query scope and Credits, call `google_search` with flat arguments:

```json
{
    "query": "battery recycling research",
    "gl": "us",
    "hl": "en",
    "num": 10
}
```

Return a table of the actual result positions, titles, source URLs, and snippets. Preserve the requested locale and capture time. Search snippets do not contain guaranteed full-page text.

For asynchronous work, retain the returned job `id` and call `get_job` with `job_id`. Read completed data from `output`. Pending work is not a completed result. For chunked MCP responses, call `get_result` with `result_id` and `next_offset`, then concatenate the chunks before parsing JSON. Check the original job after a timeout; repeating a query can incur another charge.

### Download setup

Downloads require the user's destination and scoped storage credentials. Confirm media rights, destination, retention, and costs before submission. FlashData receives the storage credentials to perform the upload; those tool arguments can also be retained in client or gateway logs. Use an approved secret-input process and appropriate log controls. If none is available, leave download and download-containing batches disabled.

Download charges reserve Credits and settle by uploaded bytes. `get_pricing` returns the byte rate; a per-request quote is not a delivery-cost estimate. Private output URLs retain the storage provider's access controls.

## Supporting tools

* `get_balance`, `get_pricing`, `get_limits`, and `get_usage`: free account reads.
* `get_job`: free job-status and completed-result reads.
* `get_result`: read the remaining chunks of a large MCP response.
* `submit_batch`: submit multiple background queries. Each item consumes Credits and follows its source's restrictions.
